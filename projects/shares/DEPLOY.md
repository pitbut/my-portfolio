# Акции сайта — разворачивание

## Структура
```
schema.sql           — схема базы данных Cloudflare D1
worker/               — Cloudflare Worker (API)
index.html, cabinet.html, admin.html, login.html, register.html,
verify.html, forgot-password.html, reset-password.html,
instructions.html, css/, js/  — статичный фронтенд (уже лежит здесь же, в projects/shares/)
```

## 1. Установка Wrangler (CLI Cloudflare)
```bash
npm install -g wrangler
wrangler login
```

## 2. Создание базы данных D1
```bash
cd worker
wrangler d1 create site_shares_db
```
Скопируй выданный `database_id` и вставь в `wrangler.toml` вместо
`ЗАМЕНИ_НА_ID_ПОСЛЕ_wrangler_d1_create`.

Применить схему:
```bash
wrangler d1 execute site_shares_db --file=../schema.sql --remote
```

## 3. Деплой Worker
```bash
wrangler deploy
```
Получишь адрес вида `https://robutpit-shares-api.<аккаунт>.workers.dev` —
либо в Cloudflare Dashboard настрой Custom Domain на `api.robutpit.com`
(Workers Routes / Custom Domains), чтобы совпадало с `API_BASE` в `frontend/js/api.js`.

## 4. Фронтенд
Фронтенд уже лежит в `projects/shares/` этого репозитория — отдельно копировать
ничего не нужно, весь `pitbut/my-portfolio` уже устроен так, что `projects/shares/`
и есть публичный путь проекта. Запись в `projects.json` для `id: "shares"`
уже добавлена — при желании поднять карточку выше на главной странице портфолио,
просто перемести её объект ближе к началу массива.

## 5. Подключение оплаты (Payme / Click)

Сейчас в `handlePurchaseIntent` (`worker/src/index.js`) стоит **заглушка**
(`payment_url` ведёт на `checkout.example`). Чтобы принимать реальные карты Visa:

1. Оформи мерчант-аккаунт в **Payme Business** или **Click Merchant**
   (для Узбекистана это стандартный путь приёма карт Visa/Humo/UzCard).
2. Получи `merchant_id` и секретный ключ, сохрани их как секреты воркера:
   ```bash
   wrangler secret put PAYME_MERCHANT_ID
   wrangler secret put PAYME_SECRET_KEY
   ```
3. В `handlePurchaseIntent` замени формирование `paymentUrl` на реальный
   вызов checkout API провайдера, передав `intent_id` как `order_id`.
4. В `handlePaymentWebhook` добавь проверку подписи запроса от провайдера
   (у каждого провайдера свой алгоритм — см. их документацию по вебхукам)
   **до** зачисления акций — это критично, иначе кто угодно сможет
   вызвать вебхук напрямую и получить акции бесплатно.
5. Пропиши в дашборде провайдера URL вебхука:
   `https://api.robutpit.com/api/payment/webhook`

## 6. Админ-доступ

Права администратора выдаются только напрямую через базу данных — на сайте
нет кнопки "стать админом" (это осознанно, чтобы никто, кроме тебя, не мог
получить доступ к списку всех держателей и их данным).

1. Зарегистрируйся на сайте как обычный пользователь.
2. Узнай свой `id` (посмотри в D1 напрямую):
   ```bash
   wrangler d1 execute site_shares_db --remote \
     --command "SELECT id, email FROM users WHERE email = 'твой@email.com'"
   ```
3. Назначь себя администратором:
   ```bash
   wrangler d1 execute site_shares_db --remote \
     --command "UPDATE users SET is_admin = 1 WHERE id = ТВОЙ_ID"
   ```
4. Открой `projects/shares/admin.html` (залогинившись под этим аккаунтом) —
   там карточки «Бонус за регистрацию» (см. п.8) и «Оценка проекта и цена
   акции» (см. п.7), список всех держателей акций, сортировка по количеству
   акций, история операций каждого и поле для отправки ему сообщения
   (сообщение появится у пользователя в личном кабинете).

## 7. Новое в этой версии: оценка проекта, передача акций, сообщения участников, дивиденды

- **Цена акции задаётся вручную.** Раньше цена росла автоматически с каждой
  проданной акцией. Теперь в `admin.html` есть поле «общая сумма» — админ вводит
  свою оценку стоимости всего проекта, эндпоинт `POST /api/admin/valuation`
  сохраняет её в `site_settings`, а цена одной акции всегда пересчитывается как
  `total_valuation / total_shares_outstanding` (см. `currentPrimaryPrice` в
  `worker/src/index.js`) — то есть от **фактического** количества акций в
  обращении, а не от фиксированных 10 000, потому что дивиденды (см. ниже)
  со временем увеличивают общее число акций, как обычный bonus issue/сплит
  на бирже: доля каждого держателя от этого не размывается, потому что
  дивиденды раздаются всем пропорционально.
- **Прямая передача акций** (`POST /api/transfer`, форма в `cabinet.html`):
  любая купля-продажа между держателями на сайте технически сводится к этому —
  оплату стороны согласуют вне сайта, а здесь просто передаётся нужное
  количество акций с одного аккаунта на другой (по email или реферальному коду).
  История передач видна в кабинете каждого из участников сделки.
- **Стакан заявок теперь показывает автора каждой заявки** (`GET /api/orderbook`
  отдаёт заявки поштучно с `user_id`/`display_name`, а не агрегированно по цене),
  и по клику на чужую заявку можно отправить ей личное сообщение
  (`POST /api/messages/send`) — оно придёт получателю в общую ленту сообщений
  кабинета (`GET /api/messages`, объединяет сообщения от админа и от участников).
- **Дивиденды — бонусными акциями, без денег** (`distributeDividends` в
  `worker/src/index.js`). Админ задаёт размер месячного пула акций
  (`POST /api/admin/dividends/pool`), и он делится между всеми текущими
  держателями строго пропорционально их доле (остаток от округления вниз просто
  не раздаётся в этом месяце). Начислить можно вручную в любой момент
  (`POST /api/admin/dividends/distribute`, кнопка в `admin.html`), либо
  настроить автоматический запуск: в `wrangler.toml` уже прописан
  `[triggers] crons = ["5 0 1 * *"]` (00:05 UTC 1-го числа каждого месяца) —
  `wrangler deploy` сам зарегистрирует расписание, ничего дополнительно
  включать не нужно. История начислений — `GET /api/admin/dividends`,
  видна в `admin.html`; у каждого держателя — в его кабинете.
- **`projects/shares/instructions.html`** — публичная страница с объяснением
  всей механики (цена акции, реклама, покупка/продажа/передача, дивиденды) для
  посетителей сайта и поисковых систем.
- **Исправлен баг вторичного рынка**: при сведении заявок в `matchNewSellOrder`/
  `matchNewBuyOrder` акции зачислялись покупателю, но не списывались у продавца —
  из-за этого при каждой сделке на вторичном рынке общее количество акций
  задваивалось бы. Теперь добавляется отрицательная запись в `shares_ledger`
  для продавца на ту же сумму.

## 8. Акция за регистрацию, реферальный бонус и подтверждение email

Модель бонусов пересмотрена: акция выдаётся **за регистрацию**, а не за первую
покупку, и требует подтверждения email.

- **Регистрация больше не логинит сразу.** `POST /api/register` создаёт
  пользователя с `email_verified = 0`, сохраняет `verification_token` и
  отправляет письмо (`sendVerificationEmail`) со ссылкой на
  `projects/shares/verify.html?token=...`. Сессия и акция не выдаются, пока
  email не подтверждён — иначе можно было бы штамповать бесплатные акции на
  одноразовые почты.
- **Подтверждение** — `POST /api/verify-email { token }` (страница
  `verify.html` дёргает его сама по параметру из ссылки). Именно здесь, один
  раз, начисляется акция за регистрацию: `signup_bonus_shares` акций (по
  умолчанию 1) делятся по ставке `referral_signup_bonus_rate` (по умолчанию
  0.05 = 5%), если пользователь пришёл по реферальной ссылке — например,
  0.95 акции новому участнику и 0.05 пригласившему. Без реферала вся акция
  достаётся регистрирующемуся. Оба параметра настраиваются в `admin.html`
  (карточка «Бонус за регистрацию») через `POST /api/admin/referral-bonus`.
- **`quantity` теперь REAL, а не INTEGER** (`shares_ledger`, `transfers`,
  `sell_orders`/`buy_orders`/`trades`, `purchase_intents`) — держатель может
  владеть дробным количеством акций (например, 0.95). Все места в UI, где
  выводится количество акций, форматируют его через `.toFixed(2)`.
- **`POST /api/resend-verification { email }`** — повторная отправка письма,
  доступна со страницы входа, если логин упал с `needs_verification: true`
  (`handleLogin` теперь блокирует вход, пока email не подтверждён).
- Старый бонус «+1 акция рефереру за первую покупку приглашённого» в
  `handlePaymentWebhook` **удалён** — он заменён начислением при подтверждении
  email, описанным выше, чтобы не давать бонус дважды по разным поводам.

### Подключение реальной отправки писем

Пока секрет `RESEND_API_KEY` не задан, письма никуда не уходят — но
`sendVerificationEmail` возвращает ссылку подтверждения, и API отдаёт её же
в ответе как `dev_verify_link` (в `handleRegister`/`handleResendVerification`),
чтобы можно было тестировать регистрацию без реальной почты. Для реальной
отправки:

1. Зарегистрируйся на [resend.com](https://resend.com) (простой бесплатный
   тариф, HTTP API одним запросом — `sendVerificationEmail` уже вызывает его
   напрямую). Можно использовать любой другой провайдер (SendGrid, Postmark,
   Mailgun) — тогда просто замени тело `fetch` в `sendVerificationEmail`.
2. Создай API-ключ и сохрани как секрет воркера:
   ```bash
   wrangler secret put RESEND_API_KEY
   ```
3. Для продакшена подтверди свой домен в Resend и укажи адрес отправителя
   в `wrangler.toml` (`EMAIL_FROM`), например `"Акции сайта <noreply@robutpit.com>"`.
   Пока домен не подтверждён, можно отправлять только с их тестового адреса
   `onboarding@resend.dev` (уже стоит по умолчанию) — реальным пользователям
   такие письма иногда попадают в спам, так что для продакшена домен лучше
   подтвердить.

## 9. Защита счётчика просмотров от накрутки

Раньше `total_views` увеличивался на каждый вызов `/api/view`, а клиент вызывал
его при каждой загрузке `index.html` — стоило закрыть вкладку и открыть снова
(или почистить `localStorage`, зайти в приватном режиме, открыть в другом
браузере), и счётчик рос заново. Клиентский троттлинг в `main.js`
(`localStorage`, не чаще раза в 30 минут) — это только чтобы не дёргать API
лишний раз, он ничего не мешает обойти, потому что живёт в браузере посетителя.

Теперь `handleTrackView` дедуплицирует по IP на сервере: адрес берётся из
заголовка `CF-Connecting-IP` (его подставляет сам Cloudflare, подделать
снаружи нельзя), хэшируется (`hashIp`, SHA-256 — сырой IP в БД не хранится) и
проверяется в таблице `view_dedup`. Один и тот же IP засчитывается в
`total_views` не чаще, чем раз в `VIEW_DEDUP_MINUTES` (30) минут — дальнейшие
вызовы с того же IP в течение получаса просто отвечают `{ ok: true, counted:
false }`, не трогая счётчик. Это не защита от VPN/прокси со сменой IP — от
по-настоящему целенаправленной накрутки нужен был бы более серьёзный
антифрод, но обычное "закрыл-открыл вкладку" и очистку `localStorage` он уже
полностью останавливает.

## 10. Восстановление пароля и срок жизни ссылок

- **`POST /api/forgot-password { email }`** (страница `forgot-password.html`,
  ссылка «Забыли пароль?» на `login.html`) — если такой email существует,
  генерирует одноразовый `password_reset_token`, сохраняет его и отправляет
  письмо со ссылкой на `reset-password.html?token=...`. Специально не
  сообщает, существует ли email — иначе по ответу можно было бы перебором
  узнавать зарегистрированные адреса.
- **`POST /api/reset-password { token, password }`** (страница
  `reset-password.html`) — проверяет токен и что он не старше
  `PASSWORD_RESET_TTL_HOURS` (1 час — короче, чем токен подтверждения email,
  потому что смена пароля чувствительнее к перехвату ссылки), задаёт новый
  пароль и **разлогинивает все существующие сессии** пользователя (`DELETE
  FROM sessions`) — если ссылку кто-то перехватил, его выкинет.
- Токен подтверждения email (`verification_token`) теперь тоже ограничен по
  времени — `VERIFICATION_TTL_HOURS` (24 часа); просроченная ссылка возвращает
  `410` с `expired: true`, дальше нужно запросить письмо заново через
  `/api/resend-verification`.
- Как и с подтверждением email, пока `RESEND_API_KEY` не задан — письмо
  восстановления реально не уходит, но ссылка возвращается в ответе как
  `dev_reset_link`, чтобы протестировать без почты.

## 11. Что дальше стоит добавить (не реализовано в этой версии)

  что списание при покупке на вторичном рынке нужно оформить как

- Полный перевод инструкций (`instructions.html`) и части новых строк интерфейса

  на en/es/pt/uz/ar — сейчас переведены только `ru` и `en`, остальные языки
  автоматически показывают русский текст как запасной вариант (см. функцию
  `t()` в `js/i18n.js`).
- Rate-limiting на `/api/register`, `/api/login`, `/api/resend-verification`
  и `/api/forgot-password` от брутфорса и спама письмами.

## Юридическая рамка (не менять без пересмотра)
- Дивиденды — ТОЛЬКО бонусные акции (см. п.7), никогда не денежная выплата.
- Никакого выкупа акций деньгами проекта — только сведение продавца
  с покупателем через стакан заявок или прямая передача акций между участниками.
- На каждой странице покупки — явный дисклеймер (уже есть в `index.html`).
