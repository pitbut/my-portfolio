# 🥂 Собутыльник

Flask-модуль виртуального ИИ-собутыльника: голосовая беседа с barge-in
(можно перебить в любой момент), тосты, шутки, «чоканье» и музыка, выбор
личности и голоса, реакция на фото обстановки — всё через один
мультимодальный ИИ-API за универсальным слоем провайдеров (на старте —
Anthropic Claude).

- **Гостевое демо на главной** — до регистрации доступна короткая беседа
  (по умолчанию 4 реплики, `GUEST_DEMO_TURNS`) как реклама; история живёт
  только в сессии гостя, в БД не пишется. После лимита — призыв
  зарегистрироваться.
- **Регистрация с полноценным подтверждением email** — тот же гейт, что в
  ai-tutor/istok: пока пользователь не перейдёт по ссылке из письма, сайт
  (кроме auth/admin/статики) недоступен (`app/__init__.py: access_gate`).
  Возрастное согласие (18+) — обязательный чекбокс при регистрации.
- **Комната беседы (`/room`)** — текст и голос (браузерный Web Speech API:
  распознавание + озвучка, без отдельного платного голосового API).
  Barge-in реализован на клиенте (`app/static/js/voice.js`): как только
  распознавание слышит начало речи пользователя, озвучка ответа
  немедленно прерывается (`speechSynthesis.cancel()`). Кнопки
  тост/шутка/чокнуться/музыка отправляют заготовленный промпт-запрос той
  же ручкой `/room/message`, что и обычная реплика.
- **Фото обстановки** — кнопка «Показать обстановку» отправляет снимок
  (галерея/камера устройства через `<input type=file capture>`) на анализ
  vision-моделью; это разовый снимок по запросу пользователя, не
  постоянный поток с камеры (дешевле и не требует doступа к камере всё
  время сессии).
- **Чат поддержки (`/support`)** — текст и вложения (файл/фото) от
  пользователя администратору напрямую: вопросы про оплату/доступ,
  жалобы. Отдельно от ИИ-собеседника, отвечает лично администратор из
  `/admin/support`.
- **Админ-панель (`/admin`, один администратор, пароль `ADMIN_PASSWORD`)**
  — три уровня предохранителей от расходов на API:
  1. блокировка одного пользователя (`/admin/users/<id>/block`);
  2. блокировка всех сразу и разблокировка всех сразу
     (`/admin/users/block-all` / `unblock-all`);
  3. общий рубильник всего приложения (`AppSettings.app_enabled`) —
     мгновенно закрывает доступ вообще всем не-администраторам, с
     настраиваемым сообщением на экране отключения.

  Плюс лимиты сообщений: у каждого пользователя есть счётчик
  `messages_used` и необязательный `message_limit` (иначе действует общий
  `AppSettings.default_message_limit`); `AppSettings.limits_enabled` —
  один переключатель, который отключает проверку лимитов вообще для
  всех, если администратор решит, что она не нужна.

## Что осознанно не реализовано (и почему)

- **Реальная оплата.** `User.is_paid` — это ручной переключатель в
  карточке пользователя в админ-панели, а не интеграция с платёжным
  провайдером (ЮKassa/Stripe/др.) — конкретный провайдер не был задан.
  Администратор отмечает статус вручную по факту оплаты (например, после
  переписки в чате поддержки). Подключение реальной оплаты — отдельная
  задача, когда определитесь с провайдером.
- **Пение** — TTS браузера не поёт полноценно, поэтому «музыка» реализована
  как промпт-запрос: модель предлагает песню и «подпевает» текстом с
  эмодзи нот, озвученным обычным TTS-голосом, а не студийным вокалом.
- **Голосовой ввод/вывод** работает через `SpeechRecognition`/
  `speechSynthesis` браузера — распознавание речи широко поддержано в
  Chrome/Edge (десктоп и Android), в Safari/iOS поддержка ограничена или
  отсутствует; в таких браузерах остаётся текстовый ввод в той же комнате.

## Архитектура

Application factory (`create_app`) + блюпринты (`auth`, `main`, `chat`,
`support`, `admin`), SQLAlchemy-модели без SQLite-специфичных типов
(переключение на PostgreSQL — через `DATABASE_URL`), схема БД управляется
Flask-Migrate/Alembic.

- `app/providers/` — универсальный слой ИИ-провайдеров: `base.py`
  описывает интерфейс (`send_message`, `build_image_content`),
  `anthropic_provider.py` — первая реализация. Выбор провайдера —
  `AI_PROVIDER` в конфиге; добавление Groq/Gemini/OpenAI как
  альтернативы сводится к новому файлу с тем же интерфейсом.
- `app/companions.py` / `app/prompts.py` — фиксированный набор личностей
  собеседника и системные промпты, включая общие правила безопасности
  (не поощрять чрезмерное употребление, вождение нетрезвым, работа с
  несовершеннолетними/кризисными ситуациями — `SAFETY_RULES`,
  действуют для любой выбранной личности).
- `app/routes/chat.py` — комната беседы: история диалога хранится в БД
  (`Conversation`/`Message`) и передаётся модели как контекст (последние
  20 реплик), лимит сообщений проверяется до вызова ИИ-API (лимит не
  расходуется впустую на сам факт проверки).
- `app/routes/admin.py` — блокировки/рубильник/лимиты/поддержка, как
  описано выше.
- `app/uploads.py` — загрузка вложений (фото обстановки, файлы поддержки)
  на ImgBB — Render не хранит файлы на диске между деплоями.
- `app/email.py` — подтверждение регистрации через Resend (HTTP API,
  не SMTP — Render блокирует исходящие SMTP-соединения на бесплатном
  тарифе).

## Запуск локально

```bash
cd projects/sobutylnik
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # укажите ANTHROPIC_API_KEY, ADMIN_PASSWORD
flask db upgrade
python seed.py
python run.py
```

Откройте `http://localhost:5000`. Без `ANTHROPIC_API_KEY` регистрация,
вход и личный кабинет работают, но начать беседу нельзя — интерфейс
покажет понятную ошибку вместо падения.

## Тесты

```bash
pytest
```

Тесты `chat`/`admin` не обращаются к реальному ИИ-API — провайдер
подменяется на детерминированный фейк, чтобы проверять лимиты,
блокировки и рубильник без сетевых вызовов.
