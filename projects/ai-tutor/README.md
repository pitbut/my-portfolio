# 🎓 ИИ-репетитор

Flask-модуль «ИИ-репетитор»: персональные занятия по школьной программе с
объяснением темы, интерактивной доской, практическими заданиями и проверкой
решений по фото — всё через один мультимодальный ИИ-API (Anthropic Claude).

Реализация построена по ТЗ `Техническое задание — Модуль «ИИ-репетитор» для
сайта` и системным промптам из `ai-tutor-system-prompt.md` (Промпт А — ведение
занятия, Промпт Б — генерация программы, Промпт В — определение эмоции по
кадру). Текущая версия закрывает **MVP (9.1) + v2 (9.2) + бо́льшую часть v3
(9.3, камера подключена только для локального определения присутствия, не
для эмоций/распознавания лиц — см. ниже)**:

- регистрация/профиль, выбор аватара и голоса, выбор предмета и класса;
- **подтверждение email обязательно** — до перехода по ссылке из письма
  сайтом пользоваться нельзя вообще (гейт в `app/__init__.py:
  require_email_confirmation`, редиректит на `/auth/confirm-pending` любой
  раздел, кроме `auth`/`admin`/статики). Ссылку подтверждения показываем
  пользователю прямо на странице ТОЛЬКО в режиме разработки (`DEBUG`) —
  в проде, если письмо не дошло, доступного обхода нет специально: иначе
  подтверждение email превращается в фикцию, а не в проверку, что ученик
  реально владеет почтовым ящиком;
- **занятие целиком на голосе** — 2D-аватар (процедурное SVG-лицо) говорит
  и слушает, никакого текстового поля для ответов/вопросов в интерфейсе
  урока нет (кроме загрузки фото решения — это форма, как и было). Рот
  анимируется синхронно с речью, глаза моргают на случайном интервале,
  лёгкое покачивание + кивок в начале каждой реплики;
- **микрофон слушает между репликами, не поверх них** — включается сразу,
  как только аватар замолчал (никогда одновременно с его собственной
  озвучкой — иначе без наушников микрофон улавливает звук из колонок и
  путает собственную речь системы с ответом ученика, см. предупреждение
  ниже). Объяснение специально разбито на несколько ходов с контрольными
  вопросами по ходу темы (не только в конце), так что пауз для реплики
  ученика достаточно часто, а не только в самом конце занятия. Когда
  репетитор явно ждёт ответа — тайм-аут 18 сек × 2 попытки: сначала
  голосовой "не расслышал, повтори", потом отправка модели служебной
  пометки — она сама решает, как продолжить, не залипая на одном вопросе;
- **если ученик отошёл** — по умолчанию определяем это только косвенно: если
  служебная пометка "нет ответа" прилетает два раза подряд (два полных хода
  без единого ответа), интерфейс перестаёт слушать микрофон вообще (дальше
  это уже не "не расслышал", а риск снова поймать случайный звук), репетитор
  голосом зовёт ученика и показывает кнопку "Я здесь, продолжай" — занятие
  возобновляется только по явному клику, не по голосу. Счётчик хранится в
  `localStorage` по id занятия, переживает перезагрузку страницы между
  ходами. Если ученик разрешил камеру — `app/static/js/presence.js` сверяет
  соседние кадры на движение (без распознавания лиц, локально, видео никуда
  не отправляется) и, если движения давно нет, хватает одного пропущенного
  хода вместо двух;
- доска — **компактно, как мелом**, не текстовый дубль речи: только
  формулы, ключевые числа, короткие подписи; полноценные примеры
  появляются на доске только на этапе заданий, не во время объяснения.
  Поддерживает LaTeX (KaTeX), пошаговые решения, диаграммы и графики
  функций (canvas/SVG-рендер на клиенте);
- скрытые по умолчанию инструменты отладки на странице занятия —
  «Текст лекции» (полная история SPEECH-реплик) и «Субтитры» (текст
  текущей реплики под аватаром), ученику не показываются, пока не включить;
- эмоциональное состояние ученика — по поведенческим сигналам (подряд
  идущие ошибки в заданиях, время бездействия, фразы вроде "не понял"),
  без камеры — передаётся в промпт как `emotion_state`;
- свободный режим — разбор произвольной темы вне программы;
- загрузка фото решения и проверка через ИИ с vision;
- программа тем — фиксированный список в БД (`data/topics.csv`), с панелью
  `/admin` для добавления предметов/классов/программ/тем (пароль —
  `ADMIN_PASSWORD`);
- `/admin/students` — список всех зарегистрированных со счётчиками
  (зарегистрировано / занятий проведено / активных сейчас) и расходом
  токенов на каждого; со страницы конкретного ученика (`/admin/students/<id>`)
  видно его занятия, запланированные сессии, можно задать лимит токенов
  (дальнейшие занятия блокируются с понятной ошибкой, пока лимит не снят
  или не поднят), написать ему на почту (через `app/email.py`, тот же
  Resend) или удалить аккаунт целиком со всеми данными;
- назначение следующего занятия — поле даты/времени с проверкой интервала
  (по умолчанию не раньше чем через 3 часа).

**TTS/STT без отдельного API-ключа:** и озвучка, и распознавание речи
сделаны через браузерный Web Speech API, а не платный голосовой сервис —
ТЗ прямо допускает для TTS/STT отдельный провайдер (раздел 6), и для
портфолио-проекта нулевая стоимость и отсутствие лишнего ключа важнее
студийного качества голоса. Поддержка и набор голосов зависят от браузера
ученика.

**Известное ограничение — нет текстового запасного варианта.** С этапа
"занятие целиком на голосе" в интерфейсе урока больше нет текстового поля
вообще (кроме формы загрузки фото) — если браузер ученика не поддерживает
`SpeechRecognition` (Web Speech API STT), ответить/задать вопрос будет
нечем: интерфейс покажет сообщение об этом, но занятие не продолжить. Это
сознательный компромисс по прямому запросу — если понадобится подстраховка
для не поддерживающих браузеров, самый простой путь — вернуть скрытое по
умолчанию текстовое поле как fallback именно на случай отсутствия
`SpeechRecognition`, не как основной способ ввода.

**Камера подключена только для присутствия, не для эмоций.** Раздел 9.3 ТЗ
формулирует эмоции-по-камере как "опционально позже" даже внутри этапа v3, и
поведенческая эвристика (`app/emotion.py`) уже покрывает основной сценарий
(frustrated/confused/bored/tired/engaged) без вызовов vision-API. Отдельный,
гораздо более простой запрос камеры — только чтобы понять, сидит ли ученик
на месте (см. пункт про "если ученик отошёл" выше): `presence.js` сравнивает
яркость соседних кадров на маленьком canvas прямо в браузере, никакой ИИ и
никакая отправка видео куда-либо не участвуют. Доступ к камере запрашивается
явно, отказ ничего не ломает — просто отключается более быстрый (по одному
пропущенному ходу) вариант определения отсутствия, остаётся обычный (по
двум). `app/ai_client.py:detect_emotion` (Промпт В) для эмоций по кадру
по-прежнему не подключён и ждёт своего часа, если понадобится.

## Архитектура

Application factory (`create_app`) + блюпринты (`auth`, `onboarding`,
`main`, `lesson`), SQLAlchemy-модели без SQLite-специфичных типов
(переключение на PostgreSQL — через `DATABASE_URL`), схема БД управляется
Flask-Migrate/Alembic.

- `app/prompts.py` — промпты из ai-tutor-system-prompt.md с подстановкой
  параметров занятия. Структура занятия: история/контекст → объяснение
  с 1-2 встроенными контрольными вопросами (`stage: comprehension_check`
  может повторяться) → финальная проверка понимания → задания (только
  теперь на доске появляются полные примеры). `NO_ANSWER_MARKER` — текст,
  который клиент подставляет вместо ответа при двойном тайм-ауте тишины.
- `app/ai_client.py` — единый клиент Anthropic API: ведение занятия,
  генерация программы, определение эмоции (все три — разные вызовы одного
  и того же провайдера, раздел 6 ТЗ).
- `app/lesson_parser.py` — разбор ответа модели на блоки SPEECH/BOARD/STATE.
- `app/lesson_engine.py` — оркестрация цикла занятия и служебных эффектов
  (создание заданий, обновление прогресса, назначение следующего занятия).
- `app/avatars.py` — фиксированный набор аватаров (имя подставляется в
  промпт как `{avatar_name}`); голос хранится как имя голоса браузера
  (`User.voice_name`), выбор — на клиенте. Все аватары — один и тот же
  SVG-силуэт, различаются только `color` (заливка головы/тела/конечностей)
  и, опционально, `has_beard` — единственный аватар с бородой («Кузьмич»,
  седой наставник, оригинальный дизайн) рисует дополнительный SVG-контур
  поверх головы (`app/templates/lesson/chat.html`), под ртом, чтобы не
  перекрывать лип-синк.
- `app/static/js/tts.js` — озвучка реплик + анимация 2D SVG-аватара
  (рот/глаза/покачивание). **Важное ограничение платформы:** SpeechSynthesis
  не отдаёт свой аудиопоток наружу — подключить Web Audio API
  `AnalyserNode` и синхронизировать рот по реальной амплитуде голоса
  нельзя (это работает только с `<audio>`/`MediaStream`). Рот
  синхронизируется по событиям `boundary` (граница каждого произнесённого
  слова); если голос их не шлёт — включается запасной таймер-фолбэк на
  всё время речи. Настоящая амплитуда потребовала бы платного voice-API
  вместо браузерного TTS.
- `app/static/js/board.js` — рендер `diagram`/`graph` на доске (canvas для
  графиков функций, узлы/связи для диаграмм); схема JSON для этих типов
  описана в самом системном промпте (`app/prompts.py`, раздел 4 Промпта А).
- `app/static/js/stt.js` — единственный способ ответить/спросить во время
  занятия. Микрофон включается только после того, как аватар замолчал
  (никогда одновременно с его собственной озвучкой — иначе без наушников
  ловит звук из колонок как акустическую петлю): `barge-in` (пока
  `awaiting: none`) слушает без тайм-аута, `answer` (`awaiting:
  student_answer`/`student_confirmation`) включает тайм-аут 18 сек ×
  2 попытки. Два пропущенных хода подряд (один — если камера подтверждает
  отсутствие движения, см. `presence.js`) переключают в режим "ученик
  отошёл": микрофон выключается совсем, репетитор зовёт голосом, занятие
  возобновляется только по кнопке.
- `app/static/js/presence.js` — необязательный сигнал присутствия с камеры
  для `stt.js` (см. выше): сравнение яркости соседних кадров на маленьком
  canvas, без распознавания лиц и без отправки видео куда-либо. Отказ в
  доступе к камере ничего не ломает.
- `app/emotion.py` — эвристика `emotion_state` по поведенческим сигналам
  (без ИИ и без vision-API), вызывается из `lesson_engine` перед каждым
  ходом.
- `app/routes/admin.py` — панель `/admin`: управление предметами/классами/
  программами/темами, список учеников со счётчиками и расходом токенов,
  страница ученика (лимит токенов, письмо на почту, удаление аккаунта).
  Авторизация — общий пароль на сессию (`ADMIN_PASSWORD`), без отдельной
  роли в таблице users. `User.tokens_used` копится в `lesson_engine.py`
  после каждого вызова `ai_client.send_lesson_turn` (Anthropic отдаёт
  `usage.input_tokens`/`output_tokens` в каждом ответе); `User.token_limit`
  — необязательный потолок, при превышении новые ходы занятия блокируются
  с `AIClientError` до того, как уйдёт запрос к ИИ-API (лимит не расходуется
  впустую на сам факт проверки).

## Запуск локально

```bash
cd projects/ai-tutor
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и укажите ANTHROPIC_API_KEY
flask db upgrade
python seed.py          # заполняет предметы/классы/программы из data/*.csv
python run.py
```

Откройте `http://localhost:5000`. Без `ANTHROPIC_API_KEY` регистрация,
выбор программы и личный кабинет работают, но начать занятие нельзя —
интерфейс покажет понятную ошибку вместо падения.

## Тесты

```bash
pytest
```

Тесты `lesson_engine`/`lesson_parser` не обращаются к реальному ИИ-API —
`send_lesson_turn` подменяется на канонические ответы в формате
SPEECH/BOARD/STATE, чтобы проверять оркестрацию (создание заданий,
обновление прогресса, проверку интервала между занятиями) детерминированно.

## Наполнение новой программы через ИИ (Промпт Б)

MVP использует фиксированный список тем (раздел 9.1 ТЗ), но сам Промпт Б
реализован и доступен и офлайн-скриптом перед деплоем, и прямо из панели —
для админа без доступа к консоли:

```bash
python scripts/generate_program.py "Химия" "9 класс"
```

**Из панели:** на странице программы (`/admin/programs/<id>/topics`) кнопка
«Сгенерировать темы через ИИ» вызывает `generate_program` и показывает
черновик на отдельной странице предпросмотра — ничего не сохраняется, пока
админ не отметит нужные темы (можно поправить название/номер/описание
любой из них) и не нажмёт «Сохранить отмеченные темы». Номера по умолчанию
предлагаются продолжающими существующие темы программы (не с единицы) —
у `Topic` уникальность по `(program_id, order)`, и раньше это ловилось
только `IntegrityError` при сохранении; на сервере это тоже подстраховано
(`admin.generate_topics_save` тихо подберёт свободный номер, если
конфликт всё же случился).
