# 💧 Исток — портал о воде

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/pitbut/my-portfolio)

Flask-приложение о воде во всех смыслах: от священных источников мира до цен на
питьевую воду в магазине. Проект спроектирован с нуля как отдельное расширяемое
серверное приложение (не статичная страница), поэтому для работы требует запуска
Python/Flask-сервера — на GitHub Pages он не откроется напрямую. Для реального
онлайн-доступа проект настроен на деплой в [Render](https://render.com) (см. ниже).

## Разделы

- **Библиотека** — книги о воде (название, автор, год, жанр, описание)
- **Статьи** — рубрики, человекочитаемые URL, дата публикации
- **Каталог** — цены на питьевую воду с сортировкой; у каждой марки своя страница
  с описанием, точками продажи/оптовыми поставщиками на карте и поиском ближайших
  по геолокации браузера
- **Священные источники мира** — локация, координаты, что можно/нельзя, посещаемость, во что верят
- **Оборудование** — фильтры, кулеры, счётчики; поиск и фильтр по категориям, у
  каждой позиции своя страница; зарегистрированные и подтвердившие email
  пользователи могут добавлять новое оборудование сами (публикуется сразу с
  пометкой «не проверено» до подтверждения администрацией — см. «Панель
  модерации» ниже)
- **Опыты с водой** — наука vs мифы
- **Доставка воды** — службы доставки со сроками и ценами
- **Контакты** — контактная информация и форма сообщения (уходит в `/admin`)

Почти на каждой детальной странице (источник, марка воды, оборудование, книга,
статья, опыт, служба доставки) есть блок **отзывов с оценкой 1-5 звёзд** —
оставить отзыв может кто угодно, без регистрации (как и предложение правки),
администрация модерирует их удалением в `/admin/reviews`.

## Архитектура

```
projects/istok/
├── app/
│   ├── __init__.py       # фабрика приложения (create_app)
│   ├── models.py         # SQLAlchemy-модели
│   ├── routes/           # блюпринты: main, sacred, catalog, articles, library
│   ├── templates/        # Jinja2-шаблоны (наследуются от base.html)
│   └── static/
│       ├── css/js
│       └── img/           # локальные картинки: sacred/, books/, articles/
├── data/                  # CSV с контентом — редактируется без кода, см. ниже
├── migrations/            # Flask-Migrate (Alembic)
├── tests/                 # pytest — минимум один тест на роут
├── config.py              # конфиги dev/test/prod, переменные окружения
├── seed.py                # читает data/*.csv и наполняет БД
├── requirements.txt
└── run.py
```

Ключевые архитектурные решения:

- **Application factory + Blueprints** — `create_app()` в `app/__init__.py`,
  разделы подключены как отдельные блюпринты, что позволяет добавлять новые
  разделы без изменения существующих файлов.
- **Модели без БД-специфичных типов** — используются только стандартные типы
  SQLAlchemy, поэтому переключение с SQLite (разработка) на PostgreSQL
  (продакшен) делается через переменную окружения `DATABASE_URL`, без
  изменения `models.py`.
- **Slug + timestamps во всех подходящих моделях** — `SacredSource` и
  `Article` имеют поле `slug` для человекочитаемых URL; все модели
  наследуют `created_at`/`updated_at` через `TimestampMixin`.
- **Миграции с первого коммита** — схема БД меняется через
  `flask db migrate` / `flask db upgrade`, а не руками.

## Быстрый старт

```bash
cd projects/istok
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env            # при необходимости отредактируйте .env

flask db upgrade                # применить миграции (создаст instance/istok.db)
python seed.py                  # наполнить БД данными из data/*.csv

python run.py                   # http://localhost:5000
```

## Как редактировать контент без кода (CSV)

Весь контент сайта — не в коде, а в CSV-файлах в папке `data/`: по одному файлу
на раздел (`sacred_sources.csv`, `books.csv`, `articles.csv`, `water_brands.csv`,
`equipment.csv`, `experiments.csv`, `delivery_services.csv`). `seed.py` просто
читает эти файлы и загружает их в базу — писать Python не нужно.

**Как поменять или добавить запись:**

1. Откройте нужный CSV на GitHub (`data/sacred_sources.csv` и т.д.) — можно
   редактировать прямо в браузере (карандаш → правки → Commit), либо скачать,
   открыть в Excel / Google Таблицах, отредактировать и загрузить обратно тем же
   способом.
2. Чтобы **изменить** запись — поменяйте нужную ячейку в строке.
3. Чтобы **добавить** новую — добавьте новую строку с теми же колонками, что и у
   остальных (первая строка файла — заголовки колонок, ориентируйтесь на них).
   У `sacred_sources.csv` и `articles.csv` обязательно свой уникальный `slug`
   (латиницей, без пробелов) — по нему строится ссылка на страницу.
   Готовый образец с пояснением каждой колонки — `data/sacred_sources.TEMPLATE.csv`
   (файл не читается сайтом, он только для примера и копирования).
4. Закоммитьте изменения в `main` — Render передеплоит сайт.

**Важно:** `seed.py` подхватывает CSV автоматически только пока таблица
**пустая** (то есть на самом первом деплое). После этого сайт хранит
данные в самой базе (в том числе правки, одобренные через `/admin`, см.
ниже), и правки в CSV сами по себе на живой сайт не попадают. Чтобы
принудительно синхронизировать базу с CSV — поставьте в Render
переменную окружения `FORCE_RESEED=true`, дождитесь деплоя, затем верните
обратно в `false` (иначе каждый следующий рестарт будет стирать базу).
Это также сотрёт любые правки, одобренные через `/admin` после последней
синхронизации — так что либо используйте CSV, либо `/admin`-модерацию как
основной способ, не вперемешку без понимания, что перезапишет что.

**Про Excel и кириллицу.** Файлы сохранены с UTF-8 BOM специально для того,
чтобы Excel открывал их с правильной кодировкой по двойному клику, без
кракозябр. При сохранении из Excel следите, чтобы формат остался «CSV UTF-8»
(не просто «CSV») — тогда BOM и кодировка сохранятся правильно и при
следующем открытии файла проблем не будет.

**Важно про многострочный текст:** поля вроде `belief`/`description`/`body`
могут содержать запятые и длинные абзацы — CSV-редакторы (Excel, Google Таблицы,
редактор GitHub) сами оборачивают такие значения в кавычки при сохранении, вручную
ничего экранировать не нужно.

**Картинки.** У источников есть поле `image_url` (в `sacred_sources.csv`), у книг
и статей — `cover_url`. Значение может быть:
- ссылкой на уже готовую картинку в интернете (`https://...`) — просто вставьте
  адрес;
- или именем файла, который вы кладёте прямо в репозиторий в
  `app/static/img/sacred/`, `app/static/img/books/` или `app/static/img/articles/`
  (например, `sacred/lourdes.jpg` в колонке для источника с таким файлом в папке
  `sacred/`) — так картинки хостятся бесплатно вместе с кодом, без сторонних
  сервисов.

**Комментарий редактора.** У источников есть поле `comment` — произвольный текст,
который, если заполнен, показывается на странице источника отдельным блоком
«Комментарий редакции». Можно оставлять пустым.

**Новый раздел** (не запись, а целый новый тип контента вроде «Источники» или
«Книги») CSV-файлом не создать — для этого нужна новая модель, роут и шаблон,
это уже код (см. «Добавление нового раздела» ниже).

## Деплой на Render (реальный онлайн-доступ)

В корне репозитория лежит `render.yaml` (Render Blueprint) — он описывает web-сервис
для `projects/istok`. База данных в нём **не создаётся автоматически**: у Render
бесплатный тариф допускает только одну активную бесплатную PostgreSQL на аккаунт,
поэтому `DATABASE_URL` нужно указать вручную — либо указав уже существующую у вас
базу на Render, либо любую другую PostgreSQL (Neon, Supabase и т.п.).

1. Зайдите на [render.com](https://render.com) и авторизуйтесь через GitHub (или
   нажмите кнопку «Deploy to Render» в начале этого файла).
2. New → Blueprint → выберите репозиторий `pitbut/my-portfolio`, ветка `main`.
3. Render найдёт `render.yaml` и покажет план: `Create web service istok` —
   нажмите **Apply/Deploy Blueprint**.
4. После создания сервиса `istok` откройте его → **Environment** → добавьте
   переменную `DATABASE_URL` со значением **External Database URL** вашей
   PostgreSQL-базы (Internal хост резолвится только внутри одного региона Render —
   если сервис и база в разных регионах, используйте именно External; берётся
   со страницы этой базы в Render → Connect). Сохраните — сервис передеплоится.
5. Проверьте вкладку **Logs**: должно быть видно `flask db upgrade`, применяющий
   миграции — он создаст таблицы `books`, `articles`, `sacred_sources` и т.д.
   в вашей базе, не трогая чужие таблицы других проектов.
6. Готово — сервис будет доступен по адресу вида `https://istok.onrender.com`
   (Render покажет точный URL на странице сервиса).

**Про данные:** `startCommand` в `render.yaml` запускает `python seed.py` при
каждом старте сервиса (`flask db upgrade && python seed.py && gunicorn ...`).
Это сделано специально, потому что на бесплатном тарифе Render недоступны
Shell и One-Off Jobs — так БД гарантированно наполняется данными из CSV при
самом первом деплое, без ручных команд. При всех следующих рестартах
`seed.py` **не трогает таблицы, в которых уже есть данные** (см. раздел
«Как редактировать контент без кода» выше) — это специально, чтобы не
стирать правки, одобренные через панель модерации `/admin` (см. ниже).
Работает только с таблицами моделей `app.models`, чужие таблицы в той же
базе не трогает.

## Панель модерации правок (/admin)

Кроме редактирования CSV, у сайта есть более простой путь для мелких правок
без похода в GitHub: на странице каждого источника есть блок «✏️ Предложить
правку» — любой посетитель может предложить новый текст для одного из полей
(во что верят / что можно / что нельзя / описание / комментарий). Предложение
не публикуется само — оно попадает в очередь на модерацию.

Смотреть и одобрять/отклонять предложения можно на `/admin/suggestions`:

1. Откройте `https://istok.onrender.com/admin` (или `/admin/login`).
2. Введите пароль — тот, что вы задали в переменной окружения `ADMIN_PASSWORD`
   на Render (Environment вашего сервиса `istok`; если не задавали — пароль по
   умолчанию `admin-change-me`, **обязательно смените** на что-то своё, раз
   страница публичная).
3. На `/admin/suggestions` видно все предложения на модерации: текущий текст
   поля (зачёркнут) и предложенная замена. **Принять** — правка сразу же
   применяется к источнику на сайте. **Отклонить** — предложение просто
   помечается отклонённым, на сайт ничего не попадает.

Форма отправки защищена простым «honeypot»-полем от части автоматического
спама, но не имеет капчи и ограничения частоты запросов — для небольшого
личного портала этого достаточно, но не рассчитывайте на защиту от
целенаправленной атаки.

**Важный компромисс:** после того как через `/admin` одобрена хотя бы одна
правка, база и CSV-файлы расходятся — CSV перестаёт быть источником истины,
пока вы не сделаете `FORCE_RESEED=true` (см. выше), который эту правку сотрёт.
Выберите один основной способ ведения контента (CSV **или** `/admin`) и
используйте второй только для быстрых точечных правок, если понимаете, что
он не переживёт следующую синхронизацию с CSV.

В панели модерации пять разделов (переключаются вкладками наверху):
- **Правки источников** — предложения с публичной формы на страницах источников.
- **Точки продажи** — точки, добавленные зарегистрированными пользователями в
  каталоге воды; кнопка «Отметить проверенным» переключает бейдж
  «не проверено» → «проверено» прямо на живой странице марки воды, «Удалить» —
  убирает точку совсем (например, если это спам или недостоверный адрес).
- **Оборудование** — то же самое, но для оборудования, добавленного
  пользователями (см. раздел «Оборудование» выше).
- **Отзывы** — все отзывы со всего сайта в одном списке, с датой и ссылкой на
  объект; здесь их можно только удалить (сами отзывы публикуются сразу же,
  без модерации перед публикацией).
- **Сообщения** — то, что пришло через форму на странице «Контакты».

Бесплатный тариф Render «засыпает» после 15 минут без запросов — первое
открытие после простоя может занять 30-60 секунд.

## Аккаунты пользователей и подтверждение email

Каталог воды позволяет любому зарегистрированному и подтвердившему email
пользователю добавить точку продажи/оптового поставщика к любой марке —
регистрация нужна именно для этого (просматривать сайт можно и без аккаунта).

- `/auth/register` — регистрация по email и паролю (не короче 8 символов).
- После регистрации пользователь сразу входит на сайт, но добавлять точки
  продажи не может, пока не подтвердит email по ссылке из письма.
- `/auth/login`, `/auth/logout` — вход и выход.
- Подтверждение — по ссылке из письма (действительна 24 часа, настраивается
  через `CONFIRM_TOKEN_MAX_AGE`), либо кнопкой «отправить письмо ещё раз» в
  шапке сайта, если письмо потерялось.

**Про отправку писем.** Приложение шлёт письма через HTTP-API сервиса
[Resend](https://resend.com) (`app/email.py`), а не через SMTP напрямую —
Render (и большинство хостингов на бесплатном тарифе) блокирует исходящие
SMTP-соединения (порты 25/465/587), пропуская только обычный веб-трафик
(HTTPS), поэтому обычный вариант с Gmail SMTP на Render не работает
(соединение падает с `OSError: Network is unreachable`).

Чтобы письма реально уходили, на Render нужно задать переменные окружения
сервиса `istok`:

- `RESEND_API_KEY` — получить бесплатно на [resend.com](https://resend.com)
  (регистрация без карты): зайдите в **API Keys** → **Create API Key**.
- `MAIL_DEFAULT_SENDER` — необязательно, как подписывать письма. Без
  верификации своего домена в Resend можно отправлять только с их тестового
  адреса `onboarding@resend.dev` (используется по умолчанию) — этого
  достаточно для сайта с небольшим числом пользователей; для полноценной
  рассылки с собственного домена нужно верифицировать домен в Resend.

**Если `RESEND_API_KEY` не задан** — письма не отправляются, но регистрация
не ломается: ссылка подтверждения показывается прямо на странице (в шапке
сайта, пока email не подтверждён — не пропадает при переходах) и попадает в
лог сервиса на Render → вкладка Logs — это разработческий/аварийный запасной
вариант, для реального сайта настройте Resend.

## Переключение на PostgreSQL

В `.env` укажите:

```
DATABASE_URL=postgresql://user:password@host:5432/istok
```

и выполните `flask db upgrade` — модели останутся без изменений.

## Добавление нового раздела

1. Модель — в `app/models.py` (используйте `TimestampMixin`, при необходимости `SlugMixin`).
2. Блюпринт — новый файл в `app/routes/`, зарегистрировать в `create_app()`.
3. Шаблоны — папка в `app/templates/`, наследование от `base.html`.
4. Миграция — `flask db migrate -m "..."` → `flask db upgrade`.
5. CSV + загрузчик — `data/<раздел>.csv` и функция `load_<раздел>()` в `seed.py`
   по образцу существующих, чтобы раздел тоже пополнялся без кода.
6. Тесты — новый файл в `tests/`.
