# kompas-auger-builder

Python-библиотека для построения шнеков (винтовых спиралей конвейера/шнекового
транспортёра) в КОМПАС-3D через COM API. Строит вал и направляющие кривые
лопасти в 3D, пытается собрать из них твёрдое тело, и строит упрощённую
2D-схему с размерами.

## Поддерживаемые типы

| kind               | диаметр лопасти          | шаг            |
|---------------------|---------------------------|----------------|
| `simple`             | постоянный                | постоянный     |
| `conic`               | линейно меняется (D1→D2)  | постоянный     |
| `conic_variable`      | линейно меняется (D1→D2)  | меняется (t1→t2)|

Все три типа задаются одним датаклассом `AugerParams` и одной функцией
`build_auger(params)` — редактирование модели means поменять параметры и
вызвать функцию заново.

## Требования

- Windows + установленный КОМПАС-3D (интерфейсы, которые использует
  библиотека, относятся к API версии 5 — стабильны как минимум с v18 по v23)
- `pip install pywin32`
- КОМПАС не обязательно запускать заранее — `connect()` подключится к уже
  открытому экземпляру или запустит новый

## Установка и запуск

```bash
pip install pywin32
python example.py
```

## Использование

```python
from kompas_auger import AugerParams, build_auger

params = AugerParams(
    kind="conic_variable",
    shaft_diameter=30,       # диаметр вала, мм
    outer_diameter_start=200,  # диаметр лопасти в начале, мм
    outer_diameter_end=100,    # диаметр лопасти в конце, мм
    pitch_start=180,           # шаг витка в начале, мм
    pitch_end=90,               # шаг витка в конце, мм
    length=900,                 # длина шнека, мм
    blade_thickness=4,          # толщина лопасти, мм
)
build_auger(params)
```

Для `kind="simple"` нужны `outer_diameter` и `pitch`.
Для `kind="conic"` — `outer_diameter_start/end` и `pitch`.
Для `kind="conic_variable"` — `outer_diameter_start/end` и `pitch_start/end`.

## Что именно строится

1. **Вал** — цилиндр выдавливанием эскиза-окружности.
2. **Направляющие кривые лопасти** — по внутреннему краю (у вала) и по
   наружному краю (OD). Для `simple`/`conic` это штатные параметрические
   объекты КОМПАСа (цилиндрическая/коническая спираль) — их потом можно
   поправить прямо в дереве модели. Для `conic_variable`, где меняется и
   диаметр, и шаг одновременно, штатных объектов КОМПАСа под это нет, поэтому
   кривая строится точками (сплайн) — угол поворота считается интегрированием
   переменного шага по длине, это чистая математика в Python, без каких-либо
   допущений о версии API.
3. **Тело лопасти** — линейчатая поверхность между направляющими → оболочка
   (толщина) → булево объединение с валом.
4. **Чертёж-схема** — упрощённый вид сбоку с простановкой размеров d и L.

## Честно о надёжности

У меня не было под рукой установленного КОМПАС-3D, чтобы прогнать скрипт
целиком, поэтому части библиотеки имеют разную степень уверенности:

- **Подключение к КОМПАСу и построение вала/направляющих кривых** — основаны
  на официальной документации SDK (`help.ascon.ru/KOMPAS_SDK`), включая точные
  GUID'ы модулей и все свойства спиралей/сплайна. Это должно заработать "как
  есть" на любой актуальной версии.
- **Построение тела лопасти** (`build_blade_solid`) **и чертёж с размерами**
  (`build_drawing`) — реализованы по общеизвестному паттерну API КОМПАСа
  (`NewEntity → GetDefinition → Create`), но точные имена некоторых свойств
  (лофт/оболочка/булева операция, параметры линейного размера) могли
  измениться между версиями КОМПАСа. Обе функции обёрнуты в `try/except`: если
  вызов не пройдёт, скрипт не упадёт молча, а напечатает, что не получилось, и
  какие 2-3 клика сделать вручную в интерфейсе — к этому моменту направляющие
  кривые лопасти уже будут построены и видны в дереве модели, так что ручная
  достройка тела занимает буквально пару минут.

Если что-то из experimental-части не заработает на вашей версии — пришлите
текст исключения, по нему легко поправить конкретное имя свойства.
