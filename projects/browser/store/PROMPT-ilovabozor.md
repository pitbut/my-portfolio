## Что такое PitBrowser и игры .pitapp

PitBrowser — мой браузер для Android. На его главном экране — установленные игры и приложения.
Игра — это обычный сайт (HTML/JS/CSS, картинки, звуки, wasm), упакованный в zip с расширением
`.pitapp`. Браузер устанавливает её на телефон, запускает на весь экран без интернета и через
библиотеку PitSDK даёт доступ к датчикам, вибрации, Bluetooth, камере и т.д. — только если это
разрешение объявлено в `manifest.json` и пользователь согласился.

Браузер устанавливает игру, когда пользователь открывает **https**-ссылку на файл, у которого
**имя оканчивается на `.pitapp`** или **`Content-Type: application/x-pitapp`**. Браузер сам
показывает окно «Установить?» со списком разрешений.

User-Agent браузера содержит `PitBrowser/<версия>` — так можно понять, открыт ли магазин в
PitBrowser (показывать «Установить») или в обычном браузере (показывать «Сначала установите
PitBrowser» со ссылкой на страницу PitBrowser в IlovaBozor).

### Формат пакета — проверяй ровно эти правила (так же проверяет браузер)

- zip-архив, `manifest.json` в **корне** архива;
- всего распакованных данных не больше **200 МБ**, файлов не больше **5000**;
- пути внутри архива: без `..`, без `.` как сегмента, без пустых сегментов, без ведущего `/`,
  без `\` и нулевого байта (защита от zip slip), длина пути < 300;
- `manifest.json` (UTF-8 JSON, до 64 КБ):

| Поле | Правило |
|---|---|
| `id` | обязательно, regex `^[a-z0-9][a-z0-9-]{1,39}$` (становится поддоменом) |
| `name` | обязательно, 1–60 символов после trim |
| `version` | по умолчанию `"1.0.0"`, до 20 символов |
| `entry` | по умолчанию `index.html`, безопасный путь, файл должен существовать |
| `icon` | необязательно; безопасный путь, файл должен существовать (PNG 512×512 рекомендуется) |
| `description` | до 500 символов |
| `orientation` | `any` (по умолчанию) \| `portrait` \| `landscape` |
| `permissions` | массив из: `sensors`, `vibrate`, `scores`, `screen`, `headphones`, `buttons`, `camera`, `microphone`, `geolocation`, `bluetooth`, `network` — любое другое значение = ошибка |
| `scores` | необязательно: `{ "order": "desc" \| "asc", "unit": "до 20 символов" }` |

Разрешения по-русски (для страницы игры и блока «Какие данные использует и зачем»):
sensors — датчики движения и окружения; vibrate — вибрация; scores — таблица рекордов;
screen — управление экраном; headphones — наушники и кнопки гарнитуры; buttons — кнопки
громкости как игровые; camera — камера; microphone — микрофон; geolocation — местоположение;
bluetooth — Bluetooth-устройства и игры между телефонами; network — доступ в интернет
(без него игра работает только со своими файлами). Опасные: camera, microphone, geolocation,
bluetooth.

## Что сделать

### 1. Публикация (консоль разработчика)
- В мастере публикации — новый тип «Игра для PitBrowser (.pitapp)» рядом с APK/AAB.
- Разбор и проверка пакета по правилам выше; понятные ошибки по-русски.
- `id` из манифеста принадлежит разработчику, который опубликовал его первым; другой разработчик
  не может занять этот `id`. Новая версия должна иметь `version` больше предыдущей (сравнение по
  числовым частям, как semver).
- Скриншоты, категория, полное описание, что нового в версии — как у APK.
- Храни сам файл `.pitapp`, его SHA-256 и размер.

### 2. Проверка безопасности (переиспользуй конвейер APK)
- ClamAV по всему архиву.
- Проверка через Claude: соответствуют ли разрешения описанию (зачем змейке камера и
  Bluetooth?), нет ли в JS вредоносного: майнеров, фишинга (поддельные формы входа/оплаты),
  отправки данных на сторонние серверы, сильно обфусцированного кода, загрузки и исполнения
  чужого кода. Для больших пакетов отправляй в Claude манифест, список файлов и
  HTML/JS-файлы (ограничь объём разумно), не бинарники.
- Результаты — в карточке проверки, как у APK; при подозрениях — на ручную модерацию.

### 3. Каталог на сайте — строго по адресу `/games`
- `/games` — список игр: поиск, категории («Для двоих и больше по Bluetooth», «Управление
  наклоном», «Для ESP32 и устройств», «Головоломки», «Аркады»…), сортировка (популярные, новые,
  рейтинг). Мобильная вёрстка в первую очередь — магазин открывают в браузере на телефоне.
- `/games/<id>` — страница игры: иконка, скриншоты, описание, версия, размер, разрешения с
  пояснениями, отзывы и оценки (как у APK), кнопка **«Установить в PitBrowser»**.
- Скачивание: `/games/<id>/download/<version>.pitapp` с заголовками
  `Content-Type: application/x-pitapp` и
  `Content-Disposition: attachment; filename="<id>-<version>.pitapp"`; считай скачивания.
- Если открыто не в PitBrowser — вместо «Установить» показывай «Игры работают в PitBrowser» и
  ссылку на страницу PitBrowser в IlovaBozor (её я опубликую как обычное Android-приложение).

### 4. API для браузера (JSON, без входа, с rate limit)
Базовый путь `/api/pit/v1`:
- `GET /api/pit/v1/apps?q=&category=&page=` — список: `id, name, version, icon_url, short_description, rating, downloads`;
- `GET /api/pit/v1/apps/<id>` — `id, name, version, description, icon_url, download_url, sha256, size, permissions, updated_at, changelog`;
- `POST /api/pit/v1/updates` с телом `{"apps": [{"id": "...", "version": "..."}]}` → `{"updates": [{"id", "version", "download_url", "sha256", "size", "changelog"}]}` — только для игр, у которых в магазине версия новее.

### 5. Онлайн-рекорды (тоже сделай, но после пунктов 1–4)
- В консоли разработчик включает «Онлайн-рекорды» и задаёт порядок (больше/меньше лучше),
  допустимый диапазон очков и максимум отправок в минуту — простая защита от читов.
- `POST /api/pit/v1/scores` `{"app_id", "score", "level", "player", "device_id"}` — проверка
  диапазона и лимитов, `player` до 30 символов, фильтр неприличных имён;
- `GET /api/pit/v1/scores/<app_id>?level=&limit=` — таблица лидеров (лучший результат игрока);
- блок «Лучшие игроки» на странице игры.

### 6. Политика конфиденциальности PitBrowser
Страница `/pitbrowser/privacy` (нужна для публикации в RuStore): браузер не собирает и не
передаёт личные данные; история, закладки и рекорды хранятся только на телефоне; камера,
микрофон, местоположение и Bluetooth используются только сайтами и играми, которым
пользователь разрешил доступ, и только пока они открыты; онлайн-рекорды — только имя игрока и
результат, если игра их отправляет. Контакты — как в остальных документах IlovaBozor.
