# B2B Platform UZ — рабочее приложение

Flask-приложение, реализующее техническое задание из
`projects/b2b-equipment-platform-uz` (там же — полная архитектура БД,
структура интерфейса и user flow на человеческом языке). Здесь —
работающий код, не макет: реальная БД, миграции, тесты, реальная бизнес-
логика во всех модулях.

## Что реализовано

- **Модуль 1 — Авторизация и paywall.** Регистрация по email (с
  подтверждением почты) и через Google OAuth, вход/выход. «Жёсткий»
  paywall обеспечен на бэкенде (`app/decorators.py`), а не только скрытием
  ссылок в интерфейсе.
- **Модуль 2 — Заказы и автоподбор.** Мультимедийный конструктор заявки
  (фото/чертежи через ImgBB, видео/документы — внешней ссылкой),
  синхронный автоподбор исполнителей (`app/matching.py`: обязательные
  фильтры по категории услуг/габаритам/активной подписке + скоринг по
  материалу, гео-близости, рейтингу), лента заказов исполнителя, аукцион
  ставок, выбор победителя, отметка «в работе» / приёмка.
- **Модуль 3 — Профили.** Заказчик и исполнитель заполняют карточки сами
  (без участия администратора): локация с выбором точки на карте
  (Leaflet/OSM), у исполнителя — станочный парк, допустимые
  габариты/материалы/услуги.
- **Модуль 4 — Карта и гео-поиск.** Интерактивная карта исполнителей,
  фильтры, геопоиск «рядом со мной» (haversine-дистанция, без PostGIS).
- **Модуль 5 — Отзывы.** Двусторонние отзывы по завершённому заказу,
  публикация только когда оставили обе стороны, пересчёт рейтинга.
- **Модуль 6 — Арбитраж.** Открытие спора любой стороной, загрузка
  доказательств, простая админ-панель разбора и вынесения решения.
- **Модуль 7 — Telegram-бот и подписки.** Единая нотификационная шина
  (`app/notify.py`) — все события платформы (новый матч, ставка, отклик на
  барахолку/вакансию, обновление спора) проходят через одну точку входа;
  Telegram — просто ещё один канал доставки поверх неё
  (`app/telegram_bot.py`, вебхук в `app/routes/telegram.py`). Привязка
  аккаунта через deep-link, команды `/orders`, `/mybids`, `/subscription`.
  Исполнитель получает бесплатный 30-дневный пробный период автоматически
  при полном заполнении профиля; платные тарифы — заявка + ручная
  активация администратором (см. ниже про эквайринг).
- **Модуль 8 — Барахолка.** Объявления о продаже/покупке станков и
  инструмента, отклики с уведомлением автора.
- **Модуль 9 — Вакансии и резюме.** Двусторонний найм: работодатель
  публикует вакансию, соискатель — резюме; откликнуться может любая
  сторона (оба уведомляются через ту же шину).
- **Конструкторы.** У исполнителя — чекбокс «есть конструктор в штате»
  (виден в фильтре карты и в карточке), плюс отдельная категория услуг
  «Проектирование и конструирование» — так фрилансер-конструктор без
  своего цеха тоже находится через обычный поиск исполнителей.
- **Модуль 10 — Материалы и сырьё.** Отдельная от барахолки площадка,
  открытая любому зарегистрированному пользователю (не только заводу):
  объявления купли/продажи с поиском по типу и виду материала
  (`app/routes/materials_market.py`), отклики уведомляют автора.
- **Модуль 11 — Сообщения.** Прямой чат между любыми двумя
  пользователями платформы (`app/routes/chat.py`) — не привязан к заказу
  или роли, поэтому подходит и для кооперации производителей друг с
  другом, и для обращения к конструктору/фрилансеру. Каждое сообщение
  проходит через ту же нотификационную шину (`app/notify.py`), поэтому
  получатель узнаёт о нём и в Telegram, если аккаунт привязан.

Всего 58 pytest-тестов, покрывающих все перечисленные модули (включая
контроль доступа, права, полный жизненный цикл заказа и споров).

## Осознанные ограничения (честно, без притворства)

- **Payme/Click/Uzcard** не подключены — это требует реального
  мерчант-аккаунта, которого у платформы нет. Оплата тарифа сейчас —
  заявка + ручное подтверждение администратором в `/admin/subscriptions`.
  Как только появятся мерчант-креды, останется добавить их HTTP-интеграцию
  в `app/routes/settings.py::subscription_request` — вся остальная схема
  (Subscription/Payment) уже рассчитана на это.
- **Видео и документы** в заявках и объявлениях принимаются внешней
  ссылкой (YouTube/Google Диск), а не загрузкой файла — свой видеохостинг
  на бесплатном хостинге нецелесообразен.
- Матчинг и уведомления выполняются синхронно в момент запроса, а не в
  фоновой очереди — для объёма MVP это ок; вынос в Celery/RQ не требует
  переписывания логики, только смены точки вызова.

## Деплой на Render

Пошаговая инструкция (Blueprint, база данных, ключи Resend/Google/ImgBB/
Telegram) — в [DEPLOY.md](./DEPLOY.md).

## Запуск локально

```bash
cd projects/b2b-platform
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и при желании отредактируйте

flask db upgrade         # применяет все миграции
python seed.py            # заполняет регионы/города/справочники/тарифы

python run.py              # http://localhost:5000
```

Чтобы попасть в админ-панель (`/admin/disputes`, `/admin/subscriptions`):

```bash
flask create-admin owner@example.com supersecret123
```

## Тесты

```bash
pytest
```

## Переменные окружения для полноценного продакшена

Всё это работает и без них (см. `.env.example` — комментарии объясняют
запасное поведение при отсутствии ключа), но для реального продакшена
понадобится:

- `SECRET_KEY` — случайная строка.
- `DATABASE_URL` — PostgreSQL (на Render создаётся отдельно).
- `RESEND_API_KEY` — чтобы письма подтверждения email реально отправлялись.
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — кнопка «Войти через Google»
  (Authorized redirect URI = `https://<домен>/auth/google/callback`).
- `IMGBB_API_KEY` — загрузка фото (заказы, барахолка, доказательства
  в спорах).
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` —
  Telegram-бот. Создаётся через @BotFather; после деплоя один раз
  выполняется `setWebhook` (команда — в `.env.example`).

Без любого из этих ключей соответствующая функция просто не активируется
(кнопка скрывается или уведомление остаётся только in-app) — сайт не
ломается и не имитирует работу, которой на самом деле нет.
